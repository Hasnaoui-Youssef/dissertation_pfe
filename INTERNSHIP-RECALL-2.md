### O8. The overwrite experiment

**Answered, and it is better than the question I asked.** Recorded here so it does not
get lost, because this is the direct evidence for the central claim of Chapter 1 and
the report currently asserts that claim with nothing behind it.

What you did:

1. Emptied every trace-related scripting callback, so nothing of yours ran.
2. Set a minimal trace configuration from the GUI, enabling trace and nothing else.
3. Halted the device and opened the memory view at the trace unit's address region.
4. Wrote the trace unit registers by hand. The writes took effect and read back.
5. Resumed, by stepping or running to a breakpoint.
6. Re-read the registers. The configuration was the IDE's again, not yours.

The finding is therefore not that the tools cannot reach the components. They can,
and so can you, through the memory view or a script. The finding is that **the IDE
re-applies its own configuration at every resume and discards yours**, so ownership
of the trace components is never handed to the user at the moment it matters.

My O9 as originally written was wrong. It assumed the gap was a capability limit and
suggested narrowing the report's claim to the GUI. No narrowing is needed. The claim
is stronger than the report currently makes it.
