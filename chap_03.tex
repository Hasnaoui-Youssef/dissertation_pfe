\section{Requirements Analysis}
\label{sec:requirements}

This section states the requirements the work must satisfy. It separates them into functional requirements, which state what the solution does, and non-functional requirements, which state the conditions it operates under, and it then traces each requirement to the deliverable that carries it.

\section{Hardware Environment}
\label{sec:hardware}

This section describes the hardware on which the work was developed and tested. It presents the target microcontroller, the development board that carries it, the debug probe that connects the board to the host, and the trace components the target makes available.

\subsection{Microcontroller: STM32H7S3L8}
\label{subsec:target}
The main device used during the development period of the project is an STM32H7S3L8, a member of the STM32H7RS family. It carries an ARM Cortex-M7 processor \cite{cortexm7_trm} running at up to 600 MHz with a memory protection unit, a double-precision floating-point unit and separate instruction and data caches of 32 kilobytes each. The device provides 64 kilobytes of internal flash memory and 620 kilobytes of internal SRAM, and is supplied in a TFBGA225 package \cite{ds_h7s3}.

Figure \ref{fig:target_debug} shows the debug and trace components of the device and the buses that connect them.

    \label{fig:target_debug}
\end{figure}

\subsection{Development Board: NUCLEO-H7S3L8}
\label{subsec:board}
The microcontroller is used on a NUCLEO-H7S3L8. It exposes a MIPI20 connector for external debug tools, which carries the serial wire and JTAG signals together with a four-bit trace port \cite{um3276}.

\subsection{Debug Probe: STLINK-V3EC}
\label{subsec:probe}
The probe is the STLINK-V3EC embedded on the board, which supports both SWD and JTAG \cite{um3276}. It connects to the host through a USB Type-C connector and additionally provides a virtual COM port (VCP) and mass storage programming.

\subsection{Trace Resources Available on the Target}
\label{subsec:trace_resources}

These four components form the on-chip trace path of the target. The ETM emits the instruction trace, the funnel carries it toward the sink, and the TMC holds it in two kilobytes of on-chip memory. That capacity is the limit against which every capture in this work is measured. The TPIU drives the external trace port, which this work leaves unused. Table \ref{tab:trace_resources} lists them with their base addresses.

\section{Conclusion}
This chapter has stated the scope of the work, the requirements it must satisfy, and the environment in which it was produced. The hardware and the requirement set both bear on what follows.

The hardware constrains which trace route is usable. The target implements both routes by which trace leaves a processor, and the bench can use only one of them, since the probe available cannot capture a trace port. The on-chip sink is therefore the route the work takes, and its capacity of two kilobytes is the constraint against which the results are read.

The requirement set fixes the shape of the work. The functional requirements describe a pipeline running from the configuration of a trace unit to the display of an executed source line, and the non-functional requirements constrain it to hardware already present and to an existing development tool. Chapter \ref{ch:architecture} describes the structure built to satisfy them.
